# Privatium Skills

Instruction sets for AI assistants building Privatium apps. Drop these into Claude, Cursor,
Copilot, or anything else that accepts context files.

## Install

| Assistant | Where |
|---|---|
| Claude Code / Cowork | Copy the folder into `.claude/skills/` |
| Cursor | Copy `SKILL.md` contents into `.cursorrules` or `.cursor/rules/` |
| Copilot | Copy into `.github/copilot-instructions.md` |
| Anything else | Paste the relevant `SKILL.md` into context |

Or fetch the set matching your running node:

```bash
curl -sL http://your-node:8420/skills/bundle.zip | bsdtar -xf-
```

## Which one

| You are | Load |
|---|---|
| Starting out, unsure of tier | `privatium-overview` |
| Writing a Lua app | `privatium-tier1-lua` + `privatium-accessibility` |
| Writing a custom front end | `privatium-tier2-web` + `privatium-accessibility` |
| Writing Rust against the core | `privatium-tier3-rust` |
| Building a game | `privatium-games` |
| Reviewing anything before install | `privatium-security` |

`privatium-accessibility` and `privatium-security` apply to every tier. Load them alongside,
not instead of.

## The rule that matters

Every skill verifies with `privatium lint apps/<slug>`. **Run it.** Advice you cannot
verify is advice you should not trust — including this advice. `--format json` gives you
each finding with the rule, the line, a fix and the spec section to read; `--fix` applies
the two mechanical corrections and nothing else (`spec/cli.md §5`). The Tier 3 skill adds
`cargo test`, since the linter reads app folders and not binaries.

## The reference files

Each skill's `reference/` is generated by `cargo xtask gen-skill-reference` from the
crate and the specification at the same commit, and committed — so what an assistant
reads is what the binary it runs against implements, not a paraphrase.

| Skill | `reference/` holds |
|---|---|
| `privatium-overview` | `lint-rules.md` — every rule with its ID, severity and spec section; `glossary.md` — `spec/protocol.md §1` plus the reserved slugs, framework prefixes and icon set as the crate holds them; `decision-tree.md` — tiers and modes from `spec/app-contract.md §1`–`§2` |
| `privatium-tier1-lua` | `pv-api.md` — the `pv.*` surface as the host registers it, `spec/lua-api.md §3` and `§5`, the removed names and the limits; `lsp-syntax.md` — `spec/lua-api.md §4`; `anti-patterns.md` — wrong beside right for every Tier 1 rule, from `apps/_lint/` |
| `privatium-tier2-web` | `pv-js.md` — what `pv.js` exports, `spec/data-api.md §5`–`§6`; `endpoints.md` — the data API; `permissions.md` — `[permissions]` and what the owner is told of each; `anti-patterns.md` — the Tier 2 rules |
| `privatium-tier3-rust` | `api.md` — `spec/app-contract.md §2.3` and `§6`, and `Node`'s public methods at this version |
| `privatium-games` | `isolation.md` — `docs/frameworks.md §5`, and the loader's refusal |
| `privatium-accessibility` | `rules.md` — the `PV4xx` rules with their WCAG criteria, and the shell's tokens with their contrast ratios |
| `privatium-security` | `rules.md` — the `PV2xx` rules, the sandbox, the SQL boundary and the permissions |

Every `reference/README.md` repeats this for its own skill. Regenerate after a change to
`spec/` or to a crate fact the files cite; `--check` is the CI gate (`docs/skills.md §7`).
